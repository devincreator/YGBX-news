# 《每周信息参考》v3 文本与 Word 输出约定

> 已获取并研究用户提供的《每周信息参考20261016.docx》**参考版**，结构与排版实测记录见 [参考版版式说明](template-reference-20261016.md)。本 GitHub 仓库**不存储该原始 Word 文档**。参考版存在封面日期、目录缓存和附表文字不同步的问题，因此不能视作已完成核对的最终母版。发布新一期时仍须在用户当期可用的真实原件复制件上修改。

## 标题

每条使用 `序号、核心事件主标题 数据/成效副标题`。准确扼要，不加句号。必须用客观可核实的数值或具体结果；事实缺少数值时使用有意义的实际进展，不编造副标题。节次使用：
- `※保险行业`
- `※监管动态`
- `※经济与社会`
- `※同业动态`

## 正文

- **每条新闻严格一个自然段**，段内不换行，不拆成多段或小标题。
- **150–250 个汉字左右的编辑长度规范**；优先满足信息准确与单段体例，字数计量应明确排除标题、链接及末尾来源标注。若全文不足以写到下限，不靠空话凑数，应保留事实并提示未达标准。
- 顺序：**发布时间和主体 → 核心事实与具体数据/条款/方案 → 可验证背景或行业含义**。
- 不把推断写成公司公布事实；行业意义要基于材料，有分析时采用克制表述。
- 不使用大段官话、空泛评价和重复新闻背景。

## 来源

正文末尾统一 `【来源名称】`，例如 `……。【中国银行保险报】`。

在候选呈报阶段，应同时给**可点击原始网页链接**和来源名称；Word 正文仅写纯文本 `【来源名称】`，不在正文内嵌 URL。为日后审计，应在独立编辑记录中保存对应 URL。

## 候选清单

每板块默认呈报 7–9 条（有效不足则如实减少），每条展示：编号、新闻标题、报道/公告日期、实际事件日期、核心事实、值得关注之处、来源及网页链接。候选阶段不必强行写成150–250字终稿。用户选定序号后才写稿。

最终默认数量目标：保险行业 5 条、监管动态 5 条、经济与社会 7 条、同业动态 7 条，共 24 条；这一目标以 2026-10-23 至 10-29 一期实际候选数量 3/3/5/5 为基准，每个板块增加 2 条。可按实际新闻质量和用户指定调整，核验不足时不凑数。

## Word 模板安全编辑

1. **必须获取可访问的真实《每周信息参考》DOCX 原件**（本轮已获得20261016参考版；跨会话是否可访问应重新确认），依 [实测版式](template-reference-20261016.md) 检查浮动文本框、封面日期/期数位置、分节、国内/国际目录域、正文标题、段落及两张附表。
2. 在原件的**复制件**上编辑。优先替换目标段落、单元格或原有书签，不重建整个文件、不全量覆写段落样式；避免抹掉复杂 runs、超链接、目录域、分节符。
3. 更新封面日期/期数、国内资讯目录和国内正文；原参考版正文末有**两张联动附表**：国债收益率（官方日终、实际交易日）与H股保险股价。附表文字、日期列与数值必须一起核实；国际目录、正文、署名及封底默认为保留，不擅自编写或删除。
4. 逐项对照“封面日期=目标期日期（不只信文件名）、期数经确认、国内目录标题=正文标题、序号连续、正文条数与目录匹配、来源位置、附表表头日期=数据日期、附表分析截止日=实际截止日、国际内容被保留、页码/页眉页脚/页边距”。已有自动目录域和缓存，必须刷新与逐项核查，不能只修改正文。
5. 渲染 DOCX 并逐页检查分页、表格溢出、字体、加粗、错页等，再交付本地文件链接。无法渲染需说明未完成视觉核验。
6. 不在未经授权时向外部邮件、社交平台或 GitHub 发布最终周报。GitHub 仓库默认只保留 Skill 与规范，实际新闻内容由用户单独确认是否归档。

## 一条虚构占位示例（仅展示版式，不得作为新闻入选）

`1、某保险机构推出专项保障方案 覆盖新增风险场景`

`10月X日，某保险机构公布……具体保险责任及适用对象……。【机构公告】`

以上为格式占位，不构成真实新闻或可直接入稿素材。
