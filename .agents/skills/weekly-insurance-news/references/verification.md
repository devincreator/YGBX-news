# 日期、原文、数据与质量核验

## 时间

- 统一北京时间（Asia/Shanghai）。
- 未指定时，以调用当日为基准：最近一个**上周五** 00:00 至本周四 23:59；如果尚未到周四，截止调用当前时间；其他起止时间以用户指令为准。
- 分别记录 `published_at`（来源发布/正式公告日期）、`event_at`（签约、投保、首单、会议、交易等实际发生日期），以及需要时的 `disclosed_at`（首次对外披露日期）。
- 原则上要求可信报道或公告在窗口内，实际事件也发生在窗口内。窗口之前发生、但窗口内**首次披露**且与经营有实质意义的新闻可作为特例候选：显式标注实际日期及首次披露，不将此前发生的事件冒称本周落地。
- 窗口内的转载旧闻，不因重新发布日期而符合条件。来源无法说明日期则暂不入围。

## 信源顺序

1. 第一手来源：国家金融监督管理总局、人民银行、证监会、财政部、国家统计局、海关总署、最高法等官网、交易所披露、保险公司公告及官方产品条款、行业协会原始发布。
2. 权威媒体：新华社/新华网、人民网、央广网、中国银行保险报、财联社、证券日报、上海证券报、经济参考报等；媒体数据尽量回溯原始公告。
3. 聚合转载和商业媒体（新浪财经、搜狐网等）仅作线索或补充，必须辨认原文出处，核实其日期、数字及正文，不把转载日期当发生日。

**每条候选必须尝试打开并阅读正文原文**。搜索摘要或标题单独不足以支持“原文已核实”；无法全文打开时标记“待核实”并剔除出可定稿池。禁止虚构 URL。

## 必核事实字段

- 新闻主体全称；涉及合作时双方名称；
- 具体动作/产品/计划及落地阶段（拟、签署、启动、完成、批准、首单等不能混用）；
- 原报道发布时间与实际事件发生时间；
- 所有金额、数量、期限、同比、百分比、百分点的单位、口径、对比期间；
- 项目/险种涉及承保责任、适用人群、服务范围和真实执行结果；
- 事实原文 URL、信源名称、是否来自一手来源；
- 判断“可采/待核实/排除”的理由以及重复事件键。

重大数据以原始披露为准；不同媒体数据矛盾时不擅自求平均值或挑一个，先回溯原始公告。百分比的同比与百分点差异不可混淆；金额保留原币种和单位；计划值不可写成已实现值。

## 编辑记录建议

供内部筛选的每个候选保留下列信息，不全部放入最终文档：

```json
{
  "id": "P01",
  "section": "同业动态",
  "title": "主体 + 具体事件",
  "published_at": "YYYY-MM-DD",
  "event_at": "YYYY-MM-DD 或 未公开",
  "first_disclosed_in_window": false,
  "source_name": "官方披露单位",
  "source_url": "https://...",
  "fact_summary": "核实后的关键举措、金额和结果",
  "business_relevance": "为什么有经营信息增量",
  "topic_key": "主体|动作|对象",
  "duplicate_of": null,
  "verification_status": "verified",
  "decision": "candidate",
  "decision_reason": "日期合规、有实际落地和有效数据"
}
```

不得让 JSON 日期格式例子反过来变成虚构数据。若某字段来源未披露，用“未公开”，不要猜测。

## 最终发布前逐条检查

- 日期在范围内，例外首次披露已显式注明；
- 一篇正文有完整可打开原文、可追溯的至少一个真实出处；
- 数据、阶段、单位、主体无误；
- 分类准确、无负面清单项目、未重复；
- 有对领导有用的事实增量，不是抽象宣传；
- Word 文档中的文字符合 v3 格式，没有把未确认候选混入终稿。
