# Weekly run：每周两阶段工作流

本流程执行既定规则，不为每次周报创建 OpenSpec proposal。

## Phase 0：明确边界（开始前）

1. 记录北京时间当天日期、用户指定起止时间和目标板块。
2. 默认检索“上周五至本周四”，周四当天截止当前时刻；周五至下周三执行时，解释当前要覆盖的最近已发生部分，绝不检索未来。
3. 获取最近一期《每周信息参考》或已确认新闻清单，提炼 `topic_key=主体|核心动作|对象`。如用户未提供，标注“仅能本期内去重”。
4. 记录用户对各板块数量、关注公司、字数、国际资讯或数据严格度的附加要求。

## Phase 1：检索、核验、候选呈报（用户选择前）

**不触碰正式 Word 终稿。**

1. 分四板块并行开不同检索思路：官方披露、媒体报道、行业统计、公司新闻/交易所公告；按准确日期组合搜索。
2. 广泛搜集候选，先应用“日期 + 负面清单”硬筛；检查是否为本期实质新增、是否是旧闻重复报道。
3. 打开每篇候选正文/原始公告，核实标题、公司/机构主体、公告日期、事实发生日期、数字与口径。需要时交叉核实第二来源。
4. 按 `references/editorial-policy.md` 归类。某机构个别产品、合作、AI/服务项目归同业；部委保险监管制度归监管；宏观数据归经济与社会；全行业统计归保险行业。
5. 以领导视角判断信息价值：经营动作是否新的、规模是否值得关注、是否暗示行业竞争格局或经营模式变化。不能拿想象的意义代替事实。
6. 每板块展示默认 5–7 条有效候选，条目至少包含：可追溯序号、可读标题、发布时间、事件日期、核心数据/举措、收录理由、来源超链接。有效不足时说明缺口。
7. 等待用户指定序号；若用户只确认一个板块，只对已选板块定稿。不得把候选自动视为获准入稿。

**候选序号建议**：I01–I07 保险行业，R01–R07 监管，E01–E07 经济与社会，P01–P07 同业。稳定 ID 贯穿候选、确认和定稿，避免新排序导致选错新闻。

## Phase 2：已确认条目 → v3 终稿 → Word

1. 按用户确认的 ID 锁定选题与顺序；新闻有重大信息更新时回溯核验，向用户标明实质变化。
2. 每条写一句标题：`序号、核心事件主标题 数据/成效副标题`，不得有句号；每条正文单一自然段 150–250 字，按照“发布时间/主体 → 事实细节 → 行业意义”，末尾 `【来源名称】`。
3. 再次逐项核对所有数字（原始精度、币种、同比 vs 百分点、计划 vs 已完成）、日期和正文逻辑。
4. 使用真实当期 Word 原件的本地复制件，参考 [实测版式与注意事项](../references/template-reference-20261016.md) 更新封面日期、已核实期数、四板块国内目录及入选正文；**另更新国内附1国债收益率和附2H股股价，要求文字、日期、表格相匹配**。保留既有样式、浮动封面文本框、分节、目录域、页眉页脚和国际资讯；没有可访问真实原件时先交付文字，不假称套版完成。
5. 核查原参考版曾出现的三个实际错误是否解决：**封面/文件名日期不同、国内目录旧标题、附表截至日期/数据不同步**。然后检查 Word 所有页面的视觉渲染和章节分页、来源标注、目录页码；发现错误修复并复查。
6. 保存本地 `.docx` 并提供文件链接。未经用户明确授权不得发送邮件、发布文章或推送含新闻正文的文件到 GitHub。
7. 若用户允许维护历史记录，记录最终入选主题与新闻原文 URL，以便下一期按事件去重。对于尚未获准归档的内部内容，只用于当次上下文。

## 审校拦截规则

| 检查 | 不满足时的动作 |
|---|---|
| 不能打开正文或无法核实原始事件 | 降为待核实；不进入终稿 |
| 日期与窗口不符，且并非窗口内首次公开披露 | 排除 |
| 高管人事 / 单纯宣传 / 普通地方罚单等 | 直接排除 |
| 一件事重复出现，缺少实质增量 | 去重，只留最完整来源 |
| 数值矛盾、币种/增速口径不明 | 查原公告；仍不明则删去该数字或移出候选 |
| 板块不符 | 重新归类，不同时占用两个板块 |
| 有效条目不足 | 如实交付更少数量并说明，不凑数 |
| 未获用户确认入选 ID | 仅停留在候选阶段 |
| 没有 v3 DOCX 模板 / 无法视觉核验 | 明示限制；不得声称排版已保真 |

## 用户短指令的默认解释

- “找一下9.26至今天的同业动态” → 只检索同业动态、按用户时间范围、给候选与链接。
- “按照 v3 写这几条” → 只对明确选定条目编写终稿文字。
- “更新 Word” → 需要真实模板及确认选题；保留排版并输出本地文件。
- “以后同业不要人事” → 这是长期规则修改；如与现有规则一致，则解释已覆盖；否则启动 OpenSpec 变更。
